# Перекладач рунної мови — специфікація для реалізації

Завдання для Claude Code: вбудувати на сайт «Ауреліон» перекладач українська ⇄ рунна. Мовна модель не використовується: усе детерміноване, працює в браузері на статичних даних.

У цьому пакеті вже є робоче еталонне ядро (`src/runna-core.js`) і тести. Ядро не треба переписувати — його треба підключити, зробити інтерфейс і розкласти дані так, як заведено в репозиторії сайту.

## 1. Статуси даних

Канон гри — лише фрази з постів. Усе інше має бути видно як не-канон і в даних, і в інтерфейсі.

| Статус | Значення | Де живе |
|---|---|---|
| `canon-phrase` | фраза дослівно з поста | `data/corpus.json` |
| `canon` | слово, підтверджене GM | `data/lexicon.json` (поки таких немає) |
| `derived` | значення виведене зіставленням канонічних фраз | `data/lexicon.json` |
| `proposed` | вигадане, у постах немає | `data/lexicon.json`, `data/rules.json` |
| `generated` | слово, складене генератором | ніде не зберігається, обчислюється |
| `name` | власна назва, транслітерована | `data/rules.json` → `names`, `translit` |
| `compound-guess`, `unknown` | лише напрям рунна → укр | — |

## 2. Склад пакета

```
src/runna-core.js            ядро: createTranslator(data) → { toRune, toUk, stem, generate }
data/corpus.json             61 канонічна фраза (рунна, переклад, мовець, арка, дата, рядок)
data/lexicon.json            89 слів: rune, uk[] (ключі пошуку), gloss, status, confidence; variants; senses
data/rules.json              рішення D1–D8, stopwords, names, translit, registers, stemmer
data/generator.json          ваги початків / голосних / кінців складу
data/generated_reverse.json  рунне слово → українські слова (для зворотного перекладу згенерованого)
data/uk_frequent.txt         6000 частотних українських слів — вхід для generated_reverse
tests/run-tests.mjs          npm test
tests/cases.json             зафіксовані приклади
tools/build_data.py          джерело lexicon/rules/generator (редагувати тут, потім запускати)
tools/build-reverse.mjs      перегенерація generated_reverse.json
tools/freeze-cases.mjs       перезапис cases.json після свідомої зміни даних
docs/analysis.md             аналіз корпусу й перелік суперечностей для GM
```

## 3. API ядра

```js
import { createTranslator } from './runna-core.js';
const t = createTranslator({ corpus, lexicon, rules, generator, reverse });

t.toRune('Я не хочу помирати, коханий.', { register: 'standard' });
// { text: "Drau no vael'n thuul'khael shae'ren.",
//   segments: [{ src: 'Я', out: 'drau', kind: 'derived', ref: 'drau' }, …] }

t.toUk("Kaen drau khael'drath.");
// { text: '[візьми / передай] [мене / мій] [меч]', segments: […] }
```

`segments[].kind` — один зі статусів із розділу 1. `ref` — id фрази корпусу (`RN-039`) або рунне слово словника. Регістри: `standard`, `darkness`.

## 4. Алгоритм: українська → рунна

1. Увесь введений текст нормалізується (нижній регістр, лише літери й пробіли) і шукається в пам'яті фраз. Збіг → віддається канонічна рунна фраза як є, `kind: canon-phrase`.
2. Інакше текст ділиться на речення за `. ! ? …`; кожне речення знову перевіряється в пам'яті фраз.
3. Речення без збігу перекладається послівно. Для кожного слова, у такому порядку:
   1. `пані / пан / пане` перед наступним словом → саме слово пропускається, наступне транслітерується й отримує суфікс `'na`.
   2. слово є в `rules.names` → усталена назва.
   3. слово з великої літери не на початку речення → транслітерація за `rules.translit`.
   4. слово є в `rules.stopwords` → пропускається.
   5. `що`: перше в реченні → `hraen`, інакше → `vaer'n`.
   6. точний збіг зі словоформою в `lexicon.words[].uk`, потім збіг за основою (стемер, §5) → слово словника; у регістрі `darkness` застосовуються `registers.darkness.overrides`.
   7. інакше → генератор (§6), `kind: generated`.
4. `не` → `no` перед наступним словом.
5. Якщо речення питальне і перше рунне слово не входить у `rules.question_words`, на початок додається `Vael'n`.
6. Порядок слів оригіналу зберігається. Перша літера речення велика, кінцевий розділовий знак переноситься.

## 5. Стемер

Параметри в `rules.stemmer`. Слово в нижньому регістрі, апострофи прибираються; знімається зворотне `-ся/-сь`; знімається найдовше закінчення зі списку, якщо після цього лишається щонайменше 3 літери. Той самий стемер будує індекс словника під час завантаження, тому в даних зберігаються звичайні словоформи, а не основи.

Відоме обмеження: чергування в основі стемер не зводить (`вогонь` → `вогон`, `вогню` → `вогн`; `ніч` / `ночі`). Такі форми дадуть різні згенеровані слова. Для слів зі словника це лікується додаванням форм у `uk[]`.

## 6. Генератор

Вхід — основа слова. `seed = FNV-1a (32 біти) від UTF-8 основи`; генератор випадкових чисел — `mulberry32(seed)`. Склад = початок + голосний + кінець, кожен обирається зваженим вибором із `data/generator.json`. Основа до 3 літер → один склад, довша → два склади через апостроф. Якщо хоч один склад збігається з наявним коренем словника, робиться наступна спроба з того ж потоку чисел (до 20). Це гарантує, що вигадане слово не виглядає складеним зі значущих коренів.

Наслідки: те саме слово завжди дає той самий результат у будь-якому браузері; запис у базу не потрібен. Зміна ваг, стемера або словника змінює результати — після цього треба перезапустити `build-reverse` і `freeze-cases`.

## 7. Алгоритм: рунна → українська

Це підрядник, а не зв'язний переклад.

1. Увесь текст, потім кожне речення шукається в пам'яті фраз → канонічний переклад.
2. Інакше послівно: написання зводиться через `lexicon.variants`; слово словника → значення за першим правилом із `lexicon.senses`, що спрацювало (умови: `first`, `last`, `prev`, `next`, `next2`), інакше `gloss`.
3. Слова немає в словнику → `generated_reverse.json` (усі українські слова-кандидати через `/`).
4. Закінчення `'na` → «пані/пан Ім'я».
5. Складене слово, де відомий хоча б один корінь → значення коренів через `+`, `kind: compound-guess`.
6. Інакше `‹слово›`, `kind: unknown`.

## 8. Вимоги до інтерфейсу

- Два поля (вхід, результат), перемикач напряму, перемикач регістру: «Стандартна» / «Голос Темряви».
- Результат рендериться із `segments`: кожне слово підсвічене за `kind`, з легендою. Мінімум три візуально різні групи: канон (`canon-phrase`, `canon`), виведене чи запропоноване (`derived`, `proposed`, `name`), згенероване (`generated`).
- Наведення або дотик на слові показує: вихідне слово, статус, для `canon-phrase` — мовця, арку й дату з корпусу.
- Для напряму рунна → українська варіанти в квадратних дужках показуються як є; `unknown` виділяється окремо.
- Кнопка копіювання результату. Переклад відбувається під час введення, без запитів до сервера.
- Стиль, шрифти, компоненти — за наявною дизайн-системою сайту.

## 9. Розміщення даних

Рекомендація: статичні JSON у збірці сайту (разом близько 160 КБ, `generated_reverse.json` варто підвантажувати ліниво при першому зворотному перекладі). Якщо на сайті прийнято тримати контент у Supabase — три таблиці `runna_phrases`, `runna_words`, `runna_rules` з тими самими полями і лише читанням для анонімів; ядро отримує ті самі об'єкти. Запис від відвідувачів не потрібен у жодному варіанті.

## 10. Критерії приймання

- `npm test` проходить у репозиторії сайту (144 перевірки: кожна канонічна фраза в обидва боки, зафіксовані приклади, детермінованість генератора).
- Усі 61 фраза корпусу при введенні українського перекладу дають точну рунну фразу з позначкою канону.
- Жоден переклад не робить мережевих запитів.
- Статус кожного слова видно в інтерфейсі.

## 11. Як оновлювати дані

1. GM підтверджує чи виправляє слово → правка в `tools/build_data.py` (значення, `status: canon`) → `python3 tools/build_data.py`.
2. Нова канонічна фраза з поста → запис у `data/corpus.json` з наступним `RN-` номером.
3. Після будь-якої зміни: `npm run build:reverse`, перегляд відмінностей, `node tools/freeze-cases.mjs`, `npm test`.

## 12. Відкриті рішення GM

`data/rules.json` → `decisions` D1–D8. Усі позначені `proposed` або `derived` і чекають підтвердження. Назви `Xiao`, `Henri`, `Lesta`, `Nokta` у `names` — теж пропозиція; канонічні лише `Khaen` і `Vistral`.
